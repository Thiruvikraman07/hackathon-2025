PIPELINE FLOW:
--------------
Pipeline 1: JD Generator
  ↓ (generates job description from company repo)
Pipeline 2: GitHub Evaluator  
  ↓ (evaluates candidate with GitHub analysis)
Pipeline 3: Resume-JD Matcher
  ↓ (direct resume comparison, no GitHub needed)
Final Decision
  → Weighted combination of P2 + P3
  → Clear HIRE/NO-HIRE with reasons
  → Suggestions for rejected candidates

FINAL DECISION LOGIC:
---------------------
If GitHub profile exists:
  - P2 weight: 60% (GitHub analysis more important)
  - P3 weight: 40% (Resume backup)

If NO GitHub profile:
  - P2 weight: 30% (Resume from P2)
  - P3 weight: 70% (Resume analysis crucial)

Decision Thresholds:
  - 80-100: strong-hire
  - 65-79:  hire
  - 50-64:  maybe (interview but cautious)
  - 0-49:   no-hire

NO-HIRE FEATURES:
-----------------
When candidate is rejected, system provides:
1. Clear explanation WHY they were rejected
2. Specific gaps identified (experience, skills, education)
3. Actionable suggestions:
   - How many years of experience needed
   - Which skills to develop
   - GitHub portfolio recommendations
   - Education completion advice
4. Alternative role suggestions:
   - Junior positions if candidate is junior
   - Mid-level positions if candidate is mid-level
5. Interview recommendation:
   - "maybe" candidates may still get interview
   - "no-hire" candidates skip interview
